# 实时场景材质与光照调整 · 2026-11-23

本次以现有工程为布局依据，只参考图片的色彩、光照、材质和界面层级。没有从参考图提取道路或建筑位置，没有生成图片或新增替代模型。

## 检查结论与处理

| 问题 | 处理方式 | 本轮结果 |
| --- | --- | --- |
| 地面、设施与道路明度接近，材质难区分 | 在原材质族上统一月壤、涂层、金属和岩石的色彩、粗糙度及金属度 | 已调整，保留导入的颜色、法线、粗糙度、AO 贴图 |
| 整体偏冷灰，建筑体积不明确 | 暖色定向主光、偏冷的环境填充与反射，适度曝光 | 已调整，仍使用 ACES 与 sRGB 输出 |
| 接地阴影不清晰 | 4096 阴影贴图、较小的 normal bias、局部尺度 GTAO | 已调整；没有给建筑另贴假阴影或移动基座 |
| 路口出现黑色尖斑 | 修正生成道路网格的反向三角面，再重算法线 | 已修正；所有顶点位置、宽度和中心线均保持原值 |
| 地形和主图被标题、说明区挤压 | 计时移入顶部，减少重复标题，增加主地图高度，保留控制与故障提示 | 已调整 |
| 岩石轮廓明显多边形，山脊部分形体过圆 | 需要在原位置、原占地范围内做模型轮廓与拓扑细化 | 本轮未重制，材质不能解决轮廓问题 |
| 环形遗址局部结构薄，设施舱体和接缝细节不足 | 需要细化原 GLB/Blender 结构、倒角、舱门与连接部件 | 本轮未重制，也没有用参考图建筑替换现有设施 |

目前色彩、明度分层、地表细节和道路接缝有所改善，但模型轮廓与工业细节仍未达到参考图的完成度。

## 对比方法

先在现有西侧科研区取景，包含月壤、岩石、科研设施、供给设施、岔路、个人舱门与信标。使用原始场景、相同相机和相同服务端快照进行前后实时 WebGL 对比；样板验证后将参数应用到现有全场景。

运行 `npm start` 后：

- 原始局部：<http://127.0.0.1:4174/look-review.html?look=baseline>
- 调整后局部：<http://127.0.0.1:4174/look-review.html?look=unified>
- 调整后全景：<http://127.0.0.1:4174/look-review.html?look=unified&view=overview>
- 赛事控制台：<http://127.0.0.1:4174/sandbox.html>

对比页只读取一次 `/api/state`，固定镜头与快照，不取得控制权，不推进比赛。游戏页面仍使用原状态机。

## 验证与边界

- `tools/verify_lunar_look.js` 验证相机一致、道路 X/Z 顶点哈希一致、所有道路高程一致、道路数量一致和车辆位置一致。
- 原道路有 56 个朝下的顶点法线，修正后为 0；道路顶点位置没有改动。
- 原始 GLB、地图 JSON、`dist/display/map.js`、`dist/sandbox/geometry.js`、`dist/floor/`、行驶屏底图和硬件状态机均未修改。
- 本机 3456 × 1942 浏览器窗口，固定全景实测约 60 fps。画布为 3456 × 1886 CSS 像素，沿用自适应预算，实际渲染约 1816 × 991；这不是原生 3.5K 渲染性能承诺。
- 硬件联调入口、真实厘米坐标、信标/舱门/落石/月震事件及判胜约定保持不变。

实现位置：`dist/lunar-look.js` 为材质与光照参数；`dist/ruins-world.js` 修正道路面朝向并应用参数；`dist/sandbox.html` 与 `dist/sandbox/style.css` 调整电脑端界面。
