# Moonfall 双屏运行

## 两个屏幕的分工

| 屏幕 | 入口 | 内容 |
| --- | --- | --- |
| 电脑屏 | http://127.0.0.1:4174/ | 完整 3D 基地地图、两车状态、比赛计时、选路、落石、发车、暂停与恢复 |
| 27 寸行驶屏 | http://127.0.0.1:4174/floor.html | 实体机器人实际行驶的月面主赛区：月壤、废墟设施、道路、信标、舱门、月震区及飞船停靠区 |

行驶屏是游戏场景，默认不显示网格和车体包络。它使用现有 GLB/PBR 资产在 Blender 中严格正俯视渲染的背景，再将道路和动态事件按厘米坐标叠加。不是把电脑屏透视画面缩小后投到地面。

仍按已确认的三段方案换图：上下两个玩家区域分别从科研前哨、中央遗址进入撤离港；每辆车完成实际回转及换段回执后，只更新所属半屏。电脑上始终保留连续完整地图。首次开局看到科研区域，终点所在的撤离港在第三段出现。

## 启动与操作

```sh
npm ci       # 首次下载或依赖更新
npm start    # 日常运行，内置无电机模拟器
```

1. 电脑显示设置选择“扩展显示”，关闭镜像。
2. 打开电脑控制台，保持该窗口运行。
3. 点击“打开行驶屏”，拖到 27 寸屏幕，点击“全屏赛区”。工具栏会自动隐藏，移动鼠标可再次显示。
4. 在电脑端配置地图、双方选开局路线，再点击“双车发车”。

旧 `sandbox.html?floor=1` 自动进入新主赛区；旧 `display.html` 自动进入合并后的电脑控制台。`index.html` 保留独立虚拟试玩，不用于硬件双屏联调。

## 坐标和规则边界

- 唯一实体路径仍为 `dist/sandbox/geometry.js`：59.8 × 33.6 cm，左上角原点，X 向右，Y 向下。
- 底图和动态层共同使用该范围。浏览器等比例显示并留黑边，不裁切、不透视、不移动相机。全屏后仍须实测屏幕有效面积并标定。
- 机器人是实物，行驶屏默认不画另一辆虚拟车；定位及车体范围可在调试模式检查。
- 信标以实际到达激活；舱门跟随权限开启/关闭。落石保留 2 秒预警与真实绕行，当前段不会提前显示预约的未来段落石。
- 月震和余震由同一个服务端状态驱动；稳定/塌陷不会在两个屏幕上分别随机。暂停和失联冻结动态时钟。
- 第三段终点线对应 x=51，停车点为 x=53.8。到达与判胜继续读取服务端的实际定位判定。
- 主赛区的道路软边和设施是美术表达，不能替代厘米路径/安全包络作为硬件寻路数据。硬件必须接收正式路线和标定，不通过识别背景颜色自行推断道路。

电脑主控只保留一个；额外控制台只读。主赛区以 `role=floor` 订阅，不能抢占控制权。关闭主控会暂停比赛；关闭主赛区窗口不会获得任何控制权。

## 调试入口

- 电脑端“展开厘米坐标与车体包络检查”：保留原工程示意图，供联调使用。
- `floor.html?debug=1` 或行驶屏“坐标检查”：在月面场景上临时叠加网格、定位与 6 × 6 cm 车体包络。
- `window.moonfallFloor.snapshot()/world()`、`window.moonfallSandbox.snapshot()/world()`：只读诊断。

## 美术文件与复现

- `art/floor-arena/moonfall-physical-arena.blend`：可编辑的三段主赛区，各段为独立集合。
- `dist/assets/floor-arena/stage-1.png` 至 `stage-3.png`：真实 Blender 严格俯视底图，复用现有月面和设施资产。
- `dist/assets/floor-arena/layout.json`：与正式厘米路径一致的导出配置。
- `node tools/export_floor_layout.mjs` 后，用 Blender 后台执行 `tools/render_floor_arena.py` 可重新生成。
- `dist/floor/renderer.js`：动态道路、信标、舱门、裂缝、落石和终点叠加，不决定规则。

真实硬件启动：`npm run hardware -- --profile config/hardware.local.json`。定位、自动行驶、回转/制动、卡牌识别和失联停车继续按现有协议接入。本轮浏览器模拟不代表实车标定或验收通过。
